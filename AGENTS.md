# AGENTS.md

This file is the project-specific instruction set for OpenCode (and other coding agents) working in this repository.

## Project

**Desktop UI Template** — a configurable VS Code-style workbench for the browser, built with React 19, TypeScript, Vite and [vscode-elements](https://github.com/vscode-elements/elements).

The product is the **shell**, not an editor. Tabs, panes, menus, panels, the status bar and the mock views are all real interactive UI. The document area, file tree, source control and chat are intentionally mock surfaces.

## Commands

```bash
npm install          # install dependencies (also needed before the first dev run)
npm run dev          # Vite dev server, http://localhost:5173
npm run build        # tsc -b && vite build
npm run preview      # serve dist/
npm run lint         # oxlint
npm run format       # prettier --write .
npm run format:check # prettier --check .
npm run typecheck    # tsc -b
npm run test         # vitest run
npm run check        # lint + format + typecheck + test + build
```

Node 24 is expected (`.nvmrc`). The package is ESM.

## Architecture rules

- The workbench-kit transformation is staged in `ROADMAP.md`. Follow the current phase and its exit criteria instead of jumping ahead to package extraction.
- `src/layout/workbench.config.ts` is the main configuration surface. Region `enabled` flags, activity items, views and default sizes belong there. Do not hard-code layout decisions in `Workbench.tsx` if they can be expressed as config.
- `src/layout/components/*` are region components. Each region must remain independently removable; do not make one region's rendering depend on another's DOM.
- `src/views/registry.tsx` maps view IDs to components. New sidebar/panel views are registered there and referenced from config.
- `src/commands/commands.ts` is the single source of truth for actions. Menus (`src/commands/menus.ts`), the command palette, view action buttons and keyboard shortcuts all call `runWorkbenchCommand`. Add commands there first.
- `src/store/workbench-store.ts` owns serializable state and persistence. Keep transient UI state local unless it must survive reloads.
- `src/styles/tokens.css` is the only place for palette values. Use `--vscode-*` and `--app-*` custom properties in CSS; never hard-code dark/light colors in components.
- `src/data/workspace.ts` contains the mock tree and documents. Keep new mock entries consistent with the real repository structure where practical.
- `src/types/vscode-elements.d.ts` declares the custom elements used in JSX. If you introduce a new vscode-elements tag, add its props there.

## vscode-elements notes

- Register only the elements the template uses in `src/vscode-elements.ts` (deep imports into `@vscode-elements/elements/dist/...`) instead of importing the package root. This keeps the production bundle small; add a deep import when you introduce a new tag.
- Codicon CSS must be a real `<link>` with `id="vscode-codicon-stylesheet"` in `index.html`. `public/codicons` is generated by `scripts/sync-codicons.mjs` via `predev`/`prebuild` and is gitignored.
- React 19 can render custom elements directly. Use `ref` + `addEventListener` for events that React does not expose as props (`vsc-tabs-select`, `vsc-context-menu-select`).
- The tabs component is used for the bottom panel. Editor tabs use standalone `vscode-tab-header` elements because the editor needs drag reorder, middle-click close and per-tab close buttons.

## Code style

- Prettier: no semicolons, single quotes, trailing commas, 100 columns.
- TypeScript strict mode; avoid `any`, prefer explicit types at module boundaries.
- oxlint must stay clean. The project uses the oxlint + Prettier combination from the Vite React template rather than ESLint.
- Use functional React components and hooks. Keep components focused; extract reusable primitives into `src/components/`.
- Prefer native CSS over utility frameworks. Use class names prefixed by the region or view (`editor-*`, `sidebar-*`, `welcome-*`).
- Keep accessibility: buttons need labels, sashes need `role="separator"` and keyboard handling, dialogs need `aria-modal`, and focus should be restored sensibly.

## Testing

- Vitest + jsdom. Store tests live in `src/store/*.test.ts`.
- Test state transitions (tabs, clamping, toggles, persistence defaults) rather than implementation details.
- For visual changes, run the dev server and verify the shell at 1440×900 and a narrow width. The project should not introduce body scroll at desktop sizes.
- `npm run check` must pass before committing.

## Non-goals

- Do not add Monaco/CodeMirror, a real file system, a Git backend, or a real agent runtime as part of the template. Those are replacement points, not dependencies.
- Do not turn the shell into a VS Code clone in name or branding. The layout is inspired by VS Code; the product is its own template.
- Do not commit secrets, tokens or environment-specific credentials.
